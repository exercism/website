i18n Remediation · Round 1

Translate the daily loop first

A traffic-prioritized plan for the first round of translation. Instead of chasing string counts, this targets the pages a logged-in learner touches every session — and exploits the fact that most of them are already keyed at the view layer, blocked only by a handful of shared files.

The key insight

The core product loop is almost already translatable — 5 shared Ruby presenter files are what's holding it back. The dashboard, auth pages, exercise editor, and track/exercise views are largely keyed already. But each renders its nav bars and tab labels from a presenter class (app/helpers/view_components/**) that hardcodes its strings. Because these files are shared across whole classes of pages, fixing five of them unblocks the entire high-traffic surface at once.

So Round 1 is small and high-leverage: key the 5 presenter files + a few editor/mentoring leaks, and the daily loop becomes genuinely translatable — before touching a single low-traffic page (challenges, bootcamp, mailers all explicitly deferred).

02

The 5 files that unblock everything

Each is pure-Ruby with zero t() calls, and each single-handedly gates a whole class of pages. This is the highest-leverage work in the codebase — ~a few dozen strings that make dozens of already-keyed pages actually translatable.

+ nav_helpers/nav_submenus.rb 		Every page on the site — nav, user dropdown, sign-in/up CTAs Learn/Discover/Contribute/More, Sign up, Log in, Dashboard, Tracks, Mentoring, all submenu titles+descriptions

view_components/settings_nav.rb Every settings sub-page All 8 settings nav items
Pattern to establish once, reuse everywhere: these are ViewComponent-style classes building tab bars in Ruby. The first one (say site_header.rb) sets the convention for converting a hardcoded tab-bar generator to I18n.t with a companion YAML; the other four are mechanical repeats. Bundle the minor prop-string leaks (mentoring/queue.rb, try_mentoring_button.rb, student/mentoring_session.rb, profile/header.rb) into the same pass.

04

Explicitly deferred to a later round

Not in Round 1 — either low daily traffic or out of translation scope entirely. Listed so the decision is on the record.

  • Challenges (challenges/**, ~215 strings) — evergreen but low-frequency campaign/status pages. High string cost, low daily traffic.
  • Bootcamp (views + 122 React components) — confirmed out of scope.
  • Admin & maintaining — internal staff tooling, out of scope.
  • Mailers (subjects + bodies) — real gap, but a separate structural workstream (needs an I18n.t convention for mailers); not a "page" a user browses daily.
  • Notifications / Journey tails — small remaining React gaps; fold into a Round 2 cleanup once the core loop is done.
  • Missing-key fixes — pending the prod-traffic checks from the audit; treat separately from this extraction plan.
Definition of done for Round 1: the 5 presenter files + editor leaks are keyed, so a locale set to non-English renders the full daily loop — chrome, dashboard, auth, track, exercise, editor, settings, profile — in that language, with only the deferred low-traffic pages and mailers remaining in English. That's the milestone that makes a first real second-language rollout demonstrable on the pages that matter.

Basis. Surface ranking and per-page i18n state derived from a static map of config/routes.rb, the nav presenters, and the coverage data from the i18n audit (v2). "Daily-use intensity" is an editorial ranking of the core learner loop, not measured analytics — confirm against real pageview data before locking the order if you have it. Effort sizes (S/M/L) are relative estimates for the extraction work only, excluding actual translation into a target language. Out-of-scope areas (admin, maintaining, bootcamp, test, campaign mailers) are excluded throughout.
